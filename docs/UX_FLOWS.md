# PerfectPlan 关键用户流程

> 状态：已确认 `0.2`  
> 目的：作为阶段 0 的交互验收基线，后续线框、组件与端到端测试都以此为准。

## 流程 A：快速捕捉任务

**用户意图：**“我现在想到一件事，先记住，其他以后再说。”

```text
任意页面 / 全局快捷键
        ↓
弹出快速添加输入框，焦点直接在标题
        ↓
用户输入标题并按 Enter
        ↓
任务保存为 active，project_id 为空，进入收集箱
        ↓
显示短暂确认与“撤销”；输入框保留焦点，可继续新增
```

验收规则：

- 快捷添加不要求选择项目、日期或优先级。
- Esc 关闭未保存输入；若已有内容，关闭前提示丢弃或继续编辑。
- 新增失败时保留输入，并说明失败原因；不得显示假成功。
- 在列表中可使用明确的“今晚”“明天”“下周”“未指定日期”快捷项；自由自然语言解析不在 MVP 承诺中。

## 流程 B：规划今天

**用户意图：**“我有很多任务，但今天只想明确真正要做的事。”

```text
打开「今日」
        ↓
先显示：逾期、已安排到今天、昨日未完成建议
        ↓
用户从建议/任意项目选择任务，点击「设为今日重点」
        ↓
任务作为引用加入今天的重点区域（默认建议 3 项）
        ↓
用户可拖动重点排序；需要时打开日历安排具体时段
```

验收规则：

- 加入今日重点不会改变任务原项目或截止日期。
- 已安排到今天的任务不会自动成为重点，避免首页过载。
- 超过 3 项时不阻止操作，但显示轻提示，例如“今天已经选择 4 项重点”。
- 当天结束后，未完成任务仍是 active；次日用户可从“昨日未完成”手动继续。
- 用户可在“每日收尾”中勾选当天未完成的重点与已安排任务；确认后仅创建次日建议，不会自动排期或标记完成。

## 流程 C：在日历中安排和改期

**用户意图：**“我想把这个任务放进实际可用的时间。”

```text
打开「日历」周视图
        ↓
从未排期任务区拖动任务到某天的时间网格
        ↓
创建 scheduled_date + scheduled_start_at
        ↓
默认显示 30 分钟时间块，用户可拉伸以确认预计时长
        ↓
系统检查同一时段的任务总时长；超载只提示、不阻止
        ↓
用户拖到新时段 / 使用「今晚、明天、下周」快捷项
        ↓
仅更新计划时间，项目、标签、备注、截止日均保留；快捷改期会清除具体时间，保留预计时长，并支持撤销
```

验收规则：

- 拖拽前后都可撤销。
- 截止日期不等于计划时间：有截止日但未排期的任务出现在未排期区，不自动占格。
- 日历冲突只提示，允许用户覆盖安排。
- 无法完成的任务可在任务详情、今日页和通知中使用同一套延期选项。

## 流程 D：完成或延期提醒的任务

**用户意图：**“现在不能做，但我不想让这件事消失。”

```text
用户收到本地提醒 / 看到今日逾期项
        ↓
选择：完成、稍后提醒、明天、打开任务
        ├── 完成：写入 completed_at，显示撤销
        ├── 稍后提醒：只创建新的 reminder_at，不改变计划
        ├── 明天：更新 scheduled_date；如有时间块则清除具体时间并保留预计时长
        └── 打开任务：进入详情，用户做完整调整
```

验收规则：

- 提醒操作失败时，应用必须在下次打开时说明，不可悄悄吞掉。
- 完成重复任务时，生成下一实例并显示简短确认。
- 用户可以在设置中关闭提醒；关闭后任务与日历能力不受影响。

## 统一反馈规范

| 操作类型  | 反馈                     | 是否可撤销       |
| --------- | ------------------------ | ---------------- |
| 创建/编辑 | 保存状态或内联失败提示   | 编辑可再次修改   |
| 完成      | 短暂 Toast               | 是               |
| 改期/拖拽 | Toast 显示新时间         | 是               |
| 删除      | 移入回收站提示           | 是               |
| 数据导入  | 预览影响范围，确认后执行 | 通过自动备份恢复 |
