# ADR-0002：MVP 的提醒后台策略

日期：2026-09-02  
状态：已接受

## 背景

PerfectPlan 的 P4 提供本地提醒。用户需要明确知道：关闭窗口、让应用在后台运行和完全退出，分别会不会继续触发提醒。

## 决策

MVP 采用以下行为：

- PerfectPlan 正在运行时（窗口在前台或被最小化）会检查并发送本地提醒。
- 用户完全退出 PerfectPlan 后，不会再触发提醒；下次打开时，已错过的提醒会被送达为应用内提醒。
- 不自动注册开机启动，也不默认创建托盘常驻进程。
- 未来若实现后台提醒，必须由用户主动在设置中开启“关闭窗口后继续运行”，并提供清晰的“完全退出”入口。

## 原因

官方 Tauri 自动启动插件可以在 macOS、Windows 和 Linux 的系统启动时启动应用，但它并不等同于常驻后台。可靠的“退出后仍提醒”还需要托盘菜单、窗口关闭拦截、真正退出语义、单实例处理和额外的跨平台验证。

在 MVP 阶段，这些复杂性会让用户难以判断应用是否还在运行，也会增加电量、权限与支持成本。透明地限制为“运行期间提醒”更符合 PerfectPlan 本地优先、可理解的产品原则。

## 后果

- 用户可在任务详情中看到完全退出不会触发提醒的提示。
- 应用内提醒中心提供完成、稍后提醒、明天和打开任务操作，避免提醒只是一条无法行动的消息。
- P5 可在用户需求明确后，独立评估托盘常驻与可选自动启动，不改变现有提醒数据模型。
