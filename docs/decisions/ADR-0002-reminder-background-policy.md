# ADR-0002：MVP 的提醒后台策略

日期：2026-09-02  
状态：已接受

## 背景

PerfectPlan 的 P4 提供本地提醒。用户需要明确知道：关闭窗口、让应用在后台运行和完全退出，分别会不会继续触发提醒。

## 决策

MVP 采用以下行为：

- PerfectPlan 正在运行时（窗口在前台、被最小化，或主窗口关闭后驻留于系统菜单栏/任务栏）会检查并发送本地提醒。
- 用户完全退出 PerfectPlan 后，不会再触发提醒；下次打开时，已错过的提醒会被送达为应用内提醒。
- 关闭主窗口只会隐藏窗口；菜单栏/任务栏图标提供“显示今日计划”“打开 PerfectPlan”“新建任务”和“彻底退出”。点击图标可开关紧邻图标的今日任务面板；任务详情在相邻的便携详情面板中打开，无需唤起主窗口。
- 不自动注册开机启动；“彻底退出”始终是明确的菜单操作。

## 原因

官方 Tauri 自动启动插件可以在 macOS、Windows 和 Linux 的系统启动时启动应用，但它并不等同于常驻后台。托盘菜单和窗口关闭拦截解决“关闭窗口后仍提醒”的日常使用场景；“彻底退出后仍提醒”仍需要额外的系统级计划任务与跨平台验证。

在 MVP 阶段，我们不承诺“彻底退出后仍提醒”，以避免后台任务、额外权限和不透明的电量消耗；同时以明确的托盘图标与“彻底退出”菜单区分隐藏窗口和退出应用。

## 后果

- 用户可在任务详情中看到完全退出不会触发提醒的提示。
- 应用内提醒中心提供完成、稍后提醒、明天和打开任务操作，避免提醒只是一条无法行动的消息。
- 后续可在用户需求明确后，独立评估可选自动启动和彻底退出后的系统级提醒，不改变现有提醒数据模型。
