# PerfectPlan 任务模型与业务规则

> 状态：已确认 `0.2`  
> 目的：为 SQLite schema、前端状态和测试提供唯一的业务语义来源。

## 1. 核心实体

| 实体                         | 含义                           | MVP 关键关系                           |
| ---------------------------- | ------------------------------ | -------------------------------------- |
| 任务（Task）                 | 用户希望完成的一件可执行事项   | 可属于一个项目、拥有多个标签和子任务   |
| 项目（Project）              | 一组长期相关的任务             | 项目可归档，不影响其中历史任务         |
| 标签（Tag）                  | 跨项目分类维度                 | 与任务多对多                           |
| 每日计划项（DailyPlanEntry） | 某日主动选为重点的任务引用     | 不复制任务；同一任务可在不同日期被选择 |
| 提醒（Reminder）             | 某任务的一次本地提醒请求       | 仅引用任务，不改变任务计划             |
| 重复规则（RecurrenceRule）   | 为重复任务生成下一次实例的规则 | 规则归属于任务系列                     |

## 2. 任务字段

| 字段                        | 类型/示例                          | 规则                                                     |
| --------------------------- | ---------------------------------- | -------------------------------------------------------- |
| `id`                        | UUID                               | 永不复用                                                 |
| `title`                     | 非空文本                           | 创建任务唯一必填项；去除首尾空白后不能为空               |
| `notes`                     | 富文本以外的纯文本                 | MVP 不支持附件或协作文档                                 |
| `status`                    | `active` / `completed` / `trashed` | 生命周期状态；不以项目或日期推导                         |
| `project_id`                | 可空 UUID                          | 空表示任务尚未归属项目                                   |
| `parent_task_id`            | 可空 UUID                          | 非空表示子任务；MVP 只支持一层子任务                     |
| `priority`                  | `none` / `low` / `medium` / `high` | 用图标与文字表达，不能只靠颜色                           |
| `scheduled_date`            | 本地日期                           | 表示计划在某天处理，可没有具体时间                       |
| `scheduled_start_at`        | 带时区时间戳                       | 存在时显示为日历时间块；其日期应与 `scheduled_date` 一致 |
| `estimated_minutes`         | 正整数                             | 仅当用户明确估计时保存；默认无值，不伪造时长             |
| `due_date`                  | 本地日期                           | 表示最晚完成日；不会自动生成日历时间块                   |
| `completed_at`              | 时间戳                             | 仅 `completed` 状态有值                                  |
| `deleted_at`                | 时间戳                             | 仅 `trashed` 状态有值，供回收站和清理策略使用            |
| `created_at` / `updated_at` | 时间戳                             | 每次可见数据变更更新 `updated_at`                        |
| `sort_order`                | 数值                               | 仅影响同一列表中的人工排序                               |

提醒、重复规则和标签使用关联表保存，避免在任务记录中编码多个列表值。

## 3. 生命周期与状态转移

```text
新建 ──> active ──完成──> completed
             │                 │
             └──删除──> trashed <──删除──┘
                           │
                        恢复
                           ▼
                        active
```

- 新任务默认 `active` 且 `project_id = null`，因此出现在任务列表。
- 完成任务保留全部属性、子任务与历史；恢复后返回 `active`。
- 删除不是永久删除，而是进入 `trashed`；恢复时保留原项目与时间信息。
- MVP 不设置“取消”状态；用户可以删除或完成任务。若未来需要放弃原因和统计，再单独设计。
- 项目归档与任务状态无关：归档项目中的任务仍可在今天或日历中出现。

## 4. 时间语义

| 概念         | 用户问题           | 显示位置                | 是否触发提醒     |
| ------------ | ------------------ | ----------------------- | ---------------- |
| 计划日期     | 我打算哪天处理？   | 今天、日历日期列表      | 否，除非另设提醒 |
| 计划开始时间 | 我打算几点开始？   | 日/周日历时间块         | 否，除非另设提醒 |
| 预计时长     | 我预留多久？       | 时间块长度、负载提示    | 否               |
| 截止日期     | 最晚什么时候完成？ | 任务详情、今天/日历提示 | 否，除非另设提醒 |
| 提醒时间     | 希望何时被提醒？   | 系统通知与任务详情      | 是               |

规则：

1. 有截止日期的任务不会自动占用日历；用户必须明确安排时间。
2. `scheduled_date` 可以存在而 `scheduled_start_at` 为空，此时任务显示在当天的“全天/未排时段”区域。
3. 设置 `scheduled_start_at` 时，默认建议 30 分钟，但只有用户确认后才存入 `estimated_minutes`。
4. 计划日期晚于截止日期时显示警告，但允许保存；现实中用户可能必须如此安排。
5. 当地日期依据设备时区计算；MVP 不处理跨时区旅行中的自动重排。

## 5. 今日视图规则

今日视图由下列区域构成，任务可以在多个区域被引用，但数据库中仅有一条任务：

1. **今日重点**：当前日期的 `DailyPlanEntry`，按用户排序，默认最多展示 3 条；用户可额外添加，但出现“超过建议重点数”提示。
2. **今日已安排**：`status = active` 且 `scheduled_date = 今天` 的任务。
3. **逾期**：`status = active` 且 `due_date < 今天` 的任务。
4. **已完成**：`completed_at` 落在今天的任务，默认折叠。

跨日时，昨日的 `DailyPlanEntry` 只作为历史记录，不会更改任务本身；未完成任务不自动标记失败，也不自动复制到下一天。今日页面会提供“从昨日继续”建议。

每日收尾时，用户可从当天未完成的重点与已安排任务中选择需要继续的项目。系统会为次日创建 `is_focus = 0` 的 `DailyPlanEntry` 作为建议；它不改变任务的项目、状态、计划日期或截止日期。用户次日点击“设为重点”后，该条目才变为 `is_focus = 1`。

## 6. 子任务规则

- 子任务也是任务，但仅可嵌套一层，避免复杂树结构。
- 子任务默认继承父任务的项目；在 MVP 中不能被单独移动到其他项目。
- 完成父任务不强制完成子任务，但在存在未完成子任务时必须给出明确提示。
- 父任务删除时，子任务一并移入回收站；恢复父任务时一并恢复。
- 子任务可以拥有标题、状态和排序；MVP 不为子任务单独安排日历时间或提醒。

## 7. 重复任务规则

- MVP 仅支持：每天、工作日、每周指定星期、每月指定日期。
- 重复任务的每一次 occurrence 是独立任务实例，拥有独立完成时间和修改记录。
- 用户完成当前实例时，系统生成下一实例；不会提前无限生成未来任务。
- 当前实例的项目、标签、优先级、计划时间、预计时长与截止日期偏移会沿用到下一实例；重复规则随之转移，不会让已完成实例再次生成副本。
- 撤销“完成”会将重复规则还原到当前实例，并把刚生成的下一实例移入回收站，避免产生重复待办。
- 设置重复前必须先设置计划日期。每周规则默认使用当前实例的计划星期，每月规则默认使用当前实例的计划日；短月按当月最后一天安排。
- 用户删除当前实例时，提供“仅此一次”或“停止此后重复”的选择。
- 修改日期、项目或标题时，MVP 默认只修改当前实例；“修改整个系列”延后到后续版本。

## 8. 边界情况

| 情形                 | MVP 行为                                             |
| -------------------- | ---------------------------------------------------- |
| 标题为空             | 禁止保存，并保留输入内容                             |
| 已完成任务被拖入日历 | 先恢复为 active，再执行移动，并显示撤销              |
| 已删除任务被搜索到   | 默认不显示；回收站内单独搜索                         |
| 删除项目             | 禁止直接永久删除；先要求归档或移除活动任务的项目归属 |
| 标签删除             | 仅解除关联，任务本身不变                             |
| 重复任务在非工作日   | “工作日”按本机周一至周五，不含地区节假日             |
| 任务跨越午夜         | MVP 不支持跨日时间块；提示用户拆分或改为全天任务     |
