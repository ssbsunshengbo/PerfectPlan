# PerfectPlan 初版视觉与无障碍规范

> 状态：已确认的 MVP 基线 `0.2`  
> 目标：建立可直接实现的基础体验规则；品牌 Logo、插画和最终配色可在公开发布前调整。

## 1. 设计方向

关键词：**平静、清晰、可行动、不过度激励**。

PerfectPlan 不应像企业项目管理工具，也不应像用连续打卡制造焦虑的效率游戏。用户打开它时，应快速看到今天可做的事；完成、延期和整理都应得到同样平静而明确的反馈。

### 设计原则

1. **内容优先**：任务标题和时间比装饰更重要；单页只保留一个主要操作。
2. **渐进展开**：快速添加保持简洁，备注、标签、提醒等在详情中展开。
3. **时间可见**：时间块、截止日和提醒的视觉语言必须不同，避免误解。
4. **可恢复**：删除、完成、拖拽改期都有即时且可撤销的反馈。
5. **克制的愉悦感**：用细微动效和完成反馈表达进展，不用积分、排名或连续打卡压力。

## 2. 布局与组件基线

### 桌面窗口

```text
┌───────────────┬──────────────────────────────────────────────┐
│ 左侧导航      │ 页面标题 / 日期导航 / 页面主要操作            │
│ 任务          ├──────────────────────────────────────────────┤
│ 日历          │              当前页面内容                    │
│ 项目          │                                              │
│               ├──────────────────────────────────────────────┤
│ 设置          │ 快速添加栏（各页均可访问）                    │
└───────────────┴──────────────────────────────────────────────┘
```

- 最小窗口宽度：`960px`；低于该宽度时，侧栏可折叠为图标栏。
- 默认内容最大宽度：列表类页面 `920px`，避免超宽行降低可读性。
- 日历视图不限制内容宽度，但必须保留未排期任务区。
- 主要行动按钮使用清晰文字，如“添加任务”“安排时间”，不只使用图标。

### 任务行

任务行从左到右为：完成控件、标题、子任务进度、时间信息、项目/标签、优先级。次要信息在窗口变窄时按顺序隐藏，标题绝不先被挤掉。

每个任务行至少提供：点击打开详情、完成、拖拽排序/安排、键盘焦点与上下文菜单。

## 3. 颜色、排版与状态

初版采用中性浅色与深色界面，单一主色用于可交互元素；MVP 阶段不锁定品牌 Logo 或专属插画，后续可在不破坏语义颜色的前提下替换主色。默认主题跟随系统，用户可手动切换。语义颜色如下：

| 语义     | 用途                       | 额外表达方式                  |
| -------- | -------------------------- | ----------------------------- |
| 主色     | 主要按钮、焦点、选中导航   | 文字、边框或图标状态          |
| 逾期     | 逾期提示                   | “已逾期”文字 + 图标，不只红色 |
| 截止临近 | 今日/明日到期提示          | 明确日期文字                  |
| 已完成   | 完成状态                   | 勾选图标 + 可读的完成文字     |
| 警告     | 时间超载、日期晚于截止日   | 图标 + 解释和可行动建议       |
| 危险     | 永久清空回收站等不可逆操作 | 二次确认 + 明确按钮文案       |

- 正文字号不小于 `14px`，常用任务标题默认 `15–16px`。
- 行高至少为字号的 `1.4` 倍；任务行的鼠标/触控目标高度不低于 `40px`。
- 所有普通文本与背景达到 WCAG AA 对比度；非文本控件也应有足够可辨识度。
- 深色主题不是简单反色，应单独检视边框、禁用状态和日历网格对比度。

## 4. 键盘与焦点

| 动作         | 初版快捷方式   | 规则                     |
| ------------ | -------------- | ------------------------ |
| 快速添加     | `⌘/Ctrl + N`   | 打开输入框并聚焦标题     |
| 搜索         | `⌘/Ctrl + K`   | 搜索任务、项目和导航目标 |
| 完成聚焦任务 | `Space`        | 若焦点在可完成任务上     |
| 打开详情     | `Enter`        | 焦点任务或列表项         |
| 关闭浮层     | `Esc`          | 返回触发控件，不丢焦点   |
| 切换视图     | 以命令面板优先 | 首版不强塞大量记忆快捷键 |

- Tab 顺序必须与视觉阅读顺序一致。
- 焦点状态始终可见，不能仅靠浏览器默认样式或颜色细微变化。
- 拖拽操作必须有非拖拽替代路径，如“安排到…”和“上移/下移”。
- 图标按钮都必须提供可访问名称和 Tooltip。

## 5. 状态、动效与错误

- 加载超过约 200ms 时显示骨架或局部加载状态，避免界面看似失效。
- 保存为乐观更新时，失败必须回滚并给出“重试”动作。
- Toast 不应是关键信息的唯一载体；失败信息在相关任务/表单处也可见。
- 常规动效控制在 150–200ms，支持系统“减少动态效果”偏好。
- 空状态要告诉用户下一步能做什么，例如“还没有任务。按 ⌘N 记录第一件事。”

## 6. 阶段 0 验收清单

- [ ] 用户无需阅读说明即可看出如何添加任务。
- [ ] 在“今日”中，重点、已安排、逾期和已完成不会被混淆。
- [ ] 截止日和日历时间块在视觉与文字上有明确差异。
- [ ] 所有核心流程可仅用键盘完成。
- [ ] 色觉差异、深浅主题和窄窗口下仍能理解任务状态。
- [ ] 删除、改期、提醒失败等错误有可行动的恢复路径。

## 7. 已确认的 MVP 品牌边界

- 视觉基调保持平静、中性、偏个人效率工具，不采用强游戏化风格。
- MVP 不以 Logo、插画或定制字体为发布前置条件；先确保信息层级和无障碍质量。
- 默认主题跟随系统，设置中允许手动切换。
