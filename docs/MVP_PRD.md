# PerfectPlan MVP 产品需求文档

> 状态：已确认 `0.2`  
> 范围：阶段 0 的产品、信息架构与关键流程基线；可进入工程阶段。

## 1. 产品概述

PerfectPlan 是一款面向个人用户的、离线优先的桌面计划软件。它帮助用户把零散待办变成当天可执行的计划，并在任务无法按计划完成时，低成本地重新安排。

产品首发以 macOS Apple Silicon 和 Windows x64 为目标。用户下载后即可使用，无账户、无广告、无任务数量限制；数据默认只保存于当前设备。

### 一句话定位

**免费、本地优先的个人计划工具：快速记下、安排到时间、安心完成。**

## 2. 要解决的问题

市面上的个人规划工具通常落在两个极端：

- 轻量待办记录得快，但难以看见时间冲突，也难以安排一周；
- 功能丰富的规划工具常将日历、提醒、筛选或跨端能力收费，或因设置复杂而增加使用负担。

PerfectPlan 不试图取代团队项目管理工具，而专注于个人的日常执行。它的价值是减少从“我有很多事”到“我现在应该做什么”的决策摩擦。

## 3. 目标用户与核心场景

### 3.1 首发目标用户

| 用户              | 典型需求                   | 当前痛点                       |
| ----------------- | -------------------------- | ------------------------------ |
| 学生              | 作业、考试、社团、生活安排 | 任务散落在聊天、笔记和脑中     |
| 自由职业者/创作者 | 同时推进多个个人项目和交付 | 截止日期与实际执行时间混在一起 |
| 轻度知识工作者    | 管理个人工作待办与生活事务 | 现有工具收费、复杂或有隐私顾虑 |

共同特征：他们不是团队管理者；需要在电脑上集中规划，并在乎免费、快速和数据掌控感。

### 3.2 MVP 核心场景

1. **捕捉**：用户想到“周五要交报告”，不想决定归属和时间，只想立刻记下。
2. **每日选择**：早上从所有任务中挑出今天真正要完成的 1–3 件事。
3. **时间块规划**：用户把“写报告”拖到周三下午 14:00–15:30，看到当天是否已经排满。
4. **计划失效后的调整**：临时被打断后，用户一键把任务推迟到明天，而不会丢掉项目、备注和优先级。
5. **数据自主**：用户断网时仍能使用，必要时导出备份并在另一台设备手动恢复。

## 4. 目标与非目标

### 4.1 MVP 目标

- 用户可在 3 秒内记录一条仅含标题的任务。
- 用户可在 2 分钟内完成当天计划。
- 用户可在日/周日历中直观看到已安排的任务，并通过拖拽改期。
- 所有核心功能在断网状态下可用。
- 用户可导出完整任务数据，不被产品锁定。

### 4.2 非目标

- 不提供登录、账号、云同步或多人协作。
- 不接入第三方日历、邮件或消息应用。
- 不做 iOS、Android 或网页端。
- 不做 AI 自动拆解、自动排期或聊天助手。
- 不做习惯、番茄钟、附件、模板市场和复杂报表。

## 5. MVP 功能范围

### 5.1 P0：必须具备

| 模块       | 功能                                                     | 用户价值                     |
| ---------- | -------------------------------------------------------- | ---------------------------- |
| 收集箱     | 快速新增、连续新增、编辑、撤销                           | 想到即记，不被表单打断       |
| 任务       | 标题、备注、优先级、标签、项目、子任务、完成/恢复/软删除 | 足以表达普通个人待办         |
| 每日规划   | 今日重点、今日已排期、逾期、即将到来                     | 知道现在该做什么             |
| 时间       | 计划日期、具体开始时间、预计时长、截止日期、基础提醒     | 区分“何时做”与“必须何时完成” |
| 日历       | 日/周视图、拖入、拖动、拉伸、超载提示                    | 真正安排可用时间             |
| 整理与检索 | 项目、标签、搜索、基础筛选                               | 能重新找到任务               |
| 数据       | 本地 SQLite、自动备份、JSON 导入导出、CSV 导出           | 数据归用户所有               |
| 基础体验   | 键盘导航、快捷新增、深浅主题、空/错状态                  | 足够快、稳、可访问           |

### 5.2 有意延后

| 功能                 | 延后原因                   | 重新评估条件                             |
| -------------------- | -------------------------- | ---------------------------------------- |
| 完整中文自然语言解析 | 歧义与测试成本高           | 核心闭环稳定后，用户高频要求快速日期输入 |
| 复杂自定义重复       | 容易产生不可理解的实例规则 | 基础每天/工作日/周/月无法满足测试用户    |
| 外部日历集成         | OAuth、冲突与隐私范围扩大  | 用户明确将它列为首要阻碍                 |
| 后台提醒             | 平台行为差异明显           | 先验证通知在运行状态下的可靠性           |

MVP 中可提供“明天、下周、选择日期”等明确的快捷排期，但不承诺自然语言自由解析。

## 6. 信息架构

```text
PerfectPlan
├── 今日
│   ├── 今日重点（手动挑选，默认最多显示 3 项）
│   ├── 已安排到今天
│   ├── 逾期
│   └── 已完成
├── 收集箱
├── 即将到来（未来 7 天）
├── 日历（日 / 周）
├── 项目
│   ├── 全部任务
│   ├── 单个项目
│   └── 已归档项目
├── 搜索
└── 设置（主题、提醒、备份、导入导出、关于）
```

导航规则：项目是任务的组织位置；今日、即将到来和日历是从不同时间维度查看同一批任务，用户不需要复制或搬运任务。

## 7. 关键交互原则

- **标题优先**：首次保存只要求任务标题；其余内容在详情中渐进设置。
- **今天是选择，不是垃圾场**：今日重点最多展示 3 项；其他任务仍可安排到今天，但不自动成为重点。
- **日历只显示已经安排的工作**：截止日不会自动占据一个时间块。
- **每个提醒都可行动**：完成、稍后、明天、打开任务。
- **不惩罚未完成**：不自动标红羞辱；逾期需醒目但可一键重新安排。
- **危险操作可恢复**：删除进入回收站；完成和改期有短暂撤销。

## 8. 关键用户流程

详细步骤见 [UX_FLOWS.md](./UX_FLOWS.md)。

| 流程     | 起点                               | 完成结果                                   |
| -------- | ---------------------------------- | ------------------------------------------ |
| 快速捕捉 | 快捷键、收集箱或任意页面的新增按钮 | 一条活动任务被保存到收集箱                 |
| 规划今天 | 今日页                             | 用户选定 1–3 项重点，并安排必要的时间块    |
| 日历改期 | 日/周日历或提醒通知                | 任务的新计划时间被保存，原有项目与备注不变 |

## 9. 质量与隐私要求

- 断网可完成所有 P0 操作。
- 任意数据库写入失败时，界面不得展示“已保存”的假成功状态。
- 删除前不永久移除数据；用户可从回收站恢复。
- 数据导出不依赖网络且能在干净环境恢复。
- 不引入广告 SDK、行为分析 SDK 或隐蔽遥测。
- 键盘可完成新增、打开、完成、延期和切换视图；颜色不能是唯一状态提示。

## 10. 反馈与成功判断

应用不做默认行为追踪。MVP 的判断依据改为：

- 10–20 名种子用户连续使用两周后的访谈与自愿反馈；
- GitHub Issues 中的阻断性问题数量和类别；
- 用户是否愿意将原有个人任务迁入，并在访谈中描述“每天打开”；
- 对同步、外部日历、习惯和专注功能的需求排序。

## 11. 已确认决策

| 决策       | 结论                                                       |
| ---------- | ---------------------------------------------------------- |
| 首发平台   | 同时支持 macOS Apple Silicon 与 Windows x64；Linux 延后    |
| 今日重点   | 默认建议 3 项；允许用户超出，并给出轻提示                  |
| 提醒边界   | MVP 中应用完全退出后不保证提醒触发；在设置和帮助中清晰说明 |
