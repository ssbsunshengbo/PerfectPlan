# PerfectPlan 日历体验规格（P4 基线）

> 状态：P3-03 已完成；P4 日历交互待进入实现。
> 目标：把“有日期的任务”变成可理解、可调整的个人时间计划；不引入账号、外部日历或联网依赖。

## 1. 决策摘要

PerfectPlan 的日历采用 **月 / 周 / 日** 三种互补视图，而非只提供一个按日期排列的任务列表：

- **月视图**用于看日期分布、截止压力和跨日改期；不承担精确排程。
- **周视图**是桌面端的默认排程视图，用于查看一周负载、安排时间块和调整冲突。
- **日视图**用于当天专注，适合细调具体时间与时长。
- 右侧固定保留“待安排”任务栏；用户可以从这里直接拖入全天区或时间网格。
- 年视图不在 MVP 范围内。它适合长期回顾而不是高频任务安排，待真实用户提出需求后再评估。

这一模式兼顾了 Todoist 的日期浏览与时间块、TickTick 的任务-日历并排安排，以及 Sunsama 的拖拽 timeboxing 方式。[Todoist 时间块](https://staging.todoist.com/help/articles/time-blocking-in-todoist-d6Pf1uTpc) [TickTick 桌面端](https://ticktick.com/windows?language=en_US) [Sunsama Timeboxing](https://help.sunsama.com/docs/usage-guides/timeboxing/)

## 2. 范围与非目标

### 本次范围

- 本机时区下的月、周、日视图切换与前后日期导航；
- 全天任务与有具体时间的任务分区显示；
- 从待安排栏拖入日历、拖动任务块改期、拉伸任务块改预计时长；
- 项目与标签筛选、任务详情入口、完成入口；
- 冲突和当天超载的非阻断提示；
- 所有变更仅写入本地 SQLite。

### 不在本次范围

- 年视图、自然语言解析、自动排程；
- Google、Outlook、Apple 日历导入/同步；
- 跨天时间块、多人协作、时区换算；
- 对用户日程作“必须”或“不可行”的强制判断。

## 3. 时间语义

现有任务模型已足够支持第一版，不需要数据库迁移。

| 字段                 | 日历中的含义         | 拖拽后的变化                             |
| -------------------- | -------------------- | ---------------------------------------- |
| `scheduled_date`     | 打算在哪天处理       | 拖到某日或全天区时更新                   |
| `scheduled_start_at` | 从几点开始的时间块   | 拖进时间网格时写入；拖到全天区时清空     |
| `estimated_minutes`  | 时间块高度与负载估算 | 拖入时间网格时缺省为 30 分钟；拉伸时更新 |
| `due_date`           | 最晚完成日期         | 只作截止标记，绝不自动占用时间网格       |

时间存储与时区约定：

- `scheduled_date` 始终是设备本地日期的 `YYYY-MM-DD`，不带时区。
- `scheduled_start_at` 是用户在设备本地选择的日期与时间转换得到的 ISO 8601 UTC 时刻；读取时必须以当前设备本地时区显示，并校验其本地日期与 `scheduled_date` 相同。
- 夏令时不存在的本地时间不可选；重复出现的时间使用操作系统默认解析结果。MVP 不对跨时区旅行做自动重排。

若设备时区变化使 UTC 时刻在新时区落到与 `scheduled_date` 不同的日期，`scheduled_date` 仍是日历归属的唯一权威：任务继续显示在该日期，并以新时区换算出的时间显示“时区已变”标记。系统不自动改写任何字段；用户可在详情中选择“按当前时区修复”，以当前显示的时分和既有 `scheduled_date` 重建 `scheduled_start_at`。

任务可只拥有计划日期，出现在全天区；拥有计划日期和开始时间时显示为时间块。若 `estimated_minutes` 缺失，时间块按 30 分钟显示，但直到用户完成拖拽、拉伸或保存操作才写入这个缺省值。仅有日期和预计时长的任务仍是全天任务，其预计时长只参与当天负载估算。若用户把任务放到晚于截止日的时间，允许保存，但显示“已逾期”或截止警示。

## 4. 信息架构

```text
日历
├── 顶栏：今天 / 上一段 / 下一段 / 月·周·日切换 / 项目与标签筛选
├── 主日历
│   ├── 全天区：仅有计划日期的任务
│   ├── 时间网格：有开始时间与预计时长的任务
│   └── 月格：日期摘要、任务条目、截止标记
└── 待安排栏
    ├── 收集箱与未排期任务
    ├── 今日重点、逾期任务
    └── 筛选后的候选任务
```

## 5. 视图规格

### 5.1 周视图（默认）

- 显示连续 7 天；桌面端每列一天，时间轴默认覆盖 06:00–23:00，可纵向滚动。
- 顶部全天区容纳日期任务；当天任务过多时显示前 3 条和“+N”。
- 时间网格按 15 分钟对齐，最小可视块为 30 分钟。
- 同一时段重叠任务并排呈现；不自动挪动其他任务。
- 每列标题展示日期、当天安排总时长及超载提示。
- 周从周一开始；“上一段 / 下一段”固定移动 7 天，“今天”把本周含当天的周一设为锚点。

### 5.2 日视图

- 展示单日全天区、时间网格和待安排栏；默认定位到当前时间附近。
- 适合把“今日重点”逐一拖成时间块，也适合拉伸调整时长。
- 当日无时间块时，保留足够空白，避免把任务清单伪装成日历。
- “上一段 / 下一段”固定移动 1 天；从月或周点击日期进入时，该日期成为日视图锚点。

### 5.3 月视图

- 展示自然月的 6×7 日期网格，溢出日期弱化显示。
- 每天显示最多 3 条紧凑任务条和“+N 项”；截止日使用小型文本标记，而不是额外的时间块。
- 支持把任务拖到另一天以修改 `scheduled_date`，并明确清空 `scheduled_start_at`；`estimated_minutes` 保留为工作量估算。
- “+N 项”展开该日期的完整任务列表；任务排序为有具体开始时间优先、随后高优先级、再按创建时间。月格中的带时间任务仍只显示紧凑条目，不显示小时刻度。
- 点击日期进入该日的日视图；点击任务打开详情。
- “上一段 / 下一段”固定移动 1 个月，“今天”回到包含当天的自然月；月、周、日共用同一个锚点日期。

## 6. 拖拽与编辑规则

| 操作                       | 结果                                       | 反馈                           |
| -------------------------- | ------------------------------------------ | ------------------------------ |
| 待安排任务 → 某一天/全天区 | 设置 `scheduled_date`，清空具体开始时间    | 任务变为全天任务，显示短暂撤销 |
| 待安排任务 → 时间网格      | 设置日期与开始时间；未设时长则写入 30 分钟 | 显示时间块与短暂撤销           |
| 全天任务 → 时间网格        | 保留日期，写入开始时间；缺省时长为 30 分钟 | 变为时间块                     |
| 时间块 → 另一时间          | 更新日期与开始时间，保留时长               | 块平滑移动，显示新时间         |
| 拖动块底边                 | 更新 `estimated_minutes`                   | 实时显示时长，松开后保存       |
| 月格中拖动任务             | 仅更新计划日期，清空具体开始时间           | 保留项目、标签、备注与截止日   |

拖拽完成后才写入数据库；写入失败时必须回滚到原位置并显示可行动的错误提示。确定性细则：

- 拖动与拉伸均按 15 分钟吸附，最短时长 30 分钟；时间块允许恰好在 24:00 结束，但不能跨到次日。最后一个可选开始时间是 23:30；落在 23:45 的拖放会向上吸附到 23:30，键盘对话框也不提供会跨日的开始时间/时长组合。
- 从全天区拖到时间网格，或从待安排栏拖到时间网格，会将块的顶部吸附到落点；拖动已有时间块保留其时长。
- 从时间网格拖回全天区或月格时，清空具体开始时间；从一个全天日期列拖到另一个日期列时，只修改计划日期。
- 数据库中已有的跨日或超出网格任务以带警示的截断块显示，且不会被静默改写；打开其详情会提供“修复为当日结束”操作，用户确认后才保存。
- 任意两个活动时间块在同一日期的时间区间相交即为冲突；全天任务与截止日期不构成冲突。冲突只提示边框和文字，绝不阻止保存；即使当前筛选隐藏了另一任务，冲突仍按全部活动任务计算。
- 每次拖放、拉伸或键盘排期会显示一个 8 秒撤销条；新的日历变更替换旧的撤销条。撤销窗口结束或应用重启后不再提供撤销，但数据已安全落盘。

日历还必须提供等价键盘操作：选中任务后按 Enter 打开详情，按 `A` 打开“安排到…”对话框；对话框依次提供日期、全天/具体时间、时间、时长和保存按钮，Esc 关闭并不保存。保存成功或失败均以 `aria-live` 文本通知，不能把拖拽作为唯一路径。

## 7. 视觉与状态

- 用项目色作为任务块左侧色条或淡色底，不以颜色作为唯一信息；标题、时间、截止标记始终可读。
- 高优先级显示小图标/文本，不让整块红色干扰时间阅读。
- 截止日只显示“截止”或“已逾期”标记；它不等于计划时间。
- 超载是提示：第一版以每天 8 小时为固定阈值，计算当日所有活动任务的预计时长（不受当前筛选影响，已完成任务不计入）；无时长的时间块按 30 分钟估算。超过阈值时显示摘要和色彩提示，但不禁止继续安排。可用时间设置延后到设置模块，避免本阶段新增数据模型。
- 空日期显示“可拖入任务安排这一天”，而非把无日期任务自动填满。

## 7.1 待安排栏规则

- 候选任务是活动主任务的去重集合：未设计划日期的任务、今日重点、逾期任务；其中“今日重点”严格指 `daily_plan_entries` 中 `plan_date = 今天` 且 `is_focus = 1` 的任务。重点的设定/移除仍在今日视图完成，日历只引用而不改变该状态。已完成、回收站和子任务不显示。
- 同一任务若同时属于多个来源，只显示一次，优先级为逾期、今日重点、未排期；顺序再按优先级与创建时间决定。
- 项目与标签筛选采用 AND 关系：选择项目后仅保留该项目，选择标签后再保留包含该标签的任务；筛选同时作用于日历内容与待安排栏，但不会改变冲突/超载计算范围。

## 9. 实施拆分与验收

1. **P3-03**：统一日期、时间、时长编辑控件；校验 `scheduled_start_at` 必须有计划日期。
2. **P4-01**：实现日/周网格、全天区、待安排栏、月视图的只读概要与日期导航。
3. **P4-02**：实现拖入、拖动、拉伸、保存失败回滚、撤销与键盘等价操作。
4. **P4-03**：实现预计时长、全天任务显示规则、冲突与超载提示。

验收：用户能在两分钟内把 3 个未排期任务分别安排到某日和具体时间；能把一个时间块换到另一日并调整时长；截止日任务不会被自动排入时间网格；鼠标不可用时仍可通过“安排到…”完成同一操作。
